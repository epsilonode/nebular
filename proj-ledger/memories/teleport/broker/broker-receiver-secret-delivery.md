# Receiver Secret Delivery And Lease Boundary

@seam Process supervision and secret authority are orthogonal. The receiver controls lifecycle and observation; the broker controls whether, when, and for which declared slots secret values may enter one managed command subtree.
@rule Never place credential values, PINs/passphrases, decrypted CAR material, or secret-derived identifiers in PM2/systemd receiver plans, app configs, environment metadata, argv, names, logs generated by the broker, status snapshots, heartbeat facts, or persisted receiver records.
@references Receiver plans carry only opaque credential/grant references and declared injection-slot metadata. A cooperative bootstrap inside the PM2-managed target invokes a short-lived broker helper, which independently validates repository identity, recipe revision, grant generation, scopes/operations, expiry, receiver, and process attempt.
@authority The bootstrap request does not establish those facts. The broker loads durable grant/attempt records, verifies the helper's exact current parent against PM2 and operating-system process facts, re-reads the checked-in recipe selected by broker metadata, compares slot/environment declarations, and atomically claims a bounded lease before secret-store access.
@acquire Acquire secrets as late as possible through the short-lived privileged helper after PM2 start and all nonsecret preflight checks. Deliver only the admitted slots over the private bootstrap channel, convert values immediately to redacted wrappers in the target library, and terminate the helper after the bounded exchange.
@environment Construct the target environment from the recipe's explicit inheritance policy, declared nonsecret entries, and authorized credential slots. Reject duplicate/case-folded names, NULs, invalid names, undeclared slots, reserved loader/runtime variables unless explicitly policy-admitted, and any secret-bearing argv.
@launch PM2 launches the target directly with nonsecret receiver metadata. The imported runtime bootstrap completes before the application entrypoint needs credentials, installs only authorized slots in the current process, and drops ordinary transport references. PM2 never receives those values in its materialized environment.
@lease Bind `SecretLease` to repository, recipe revision, grant generation, credential reference, slot, receiver id, process attempt, target subtree identity, acquisition time, expiry, and permitted exposure mode. It is no broader or longer-lived than the local grant.
@lifetime A process-environment secret necessarily remains accessible to the authorized target and descendants for their lifetime. The managed target owns the resulting in-process value; JavaScript cannot promise memory erasure or containment from malicious same-user processes.
@restart PM2 restart starts the target without plaintext credentials and requires cooperative bootstrap to obtain a new lease after full grant validation. Never persist a plaintext lease across restart or let PM2 replay a secret environment with `--update-env`, dumps, or saved ecosystem state.
@expiry On lease/grant expiry or revocation, transition the attempt to cancellation through the receiver, stop the exact target gracefully, escalate through verified tree cleanup, release keychain/plaintext references where reachable, and record a redacted terminal fact. Runtime cooperation may support earlier in-process disposal but is not a substitute for stopping a process that inherited an expired environment secret.
@failure If keychain retrieval, validation, environment construction, child launch, heartbeat initialization, or lease journaling fails, start no target or cancel the partially started subtree. PM2 receives only a typed redacted terminal status/exit code.
@post_install If the target has installed values but the acknowledgement, helper terminal transition/exit, or deferred application import fails, the client removes only the newly installed environment names through an idempotent cleanup capability. Client cleanup narrows exposure but does not by itself prove durable lease state; ambiguous journal/IPC completion still enters broker recovery.
@output The authorized target may print its credential; V1 accepts that residual risk under the vetted-recipe/well-behaved-agent model. Bootstrap and broker code never intentionally echo, inspect for logging, or copy secret values into structured status, audit, heartbeat, or exception fields.
@unsupported A runtime without a cooperative bootstrap or admitted receiver-native secret facility returns `secret-delivery-unsupported`. Do not solve compatibility by silently adding a resident Bun wrapper or placing plaintext in PM2/systemd metadata.
@alternatives Every receiver adapter uses the same secret-delivery seam. Systemd credentials, launchd facilities, containers, schedulers, language-specific clients, or provider-operation handles may supply receiver/runtime-native delivery when they preserve repository/grant validation and avoid control-plane plaintext.
@proof Scan PM2 config/env/status/dumps, receiver plans, argv, process names, bootstrap/broker logs, heartbeats, journals, audit, IPC fixtures, crash paths, and artifacts for secrets. Test short-lived bootstrap exit, restart, expiry, revocation, bootstrap failure, unsupported runtime, forced cleanup, slot collision, and alternative-receiver fixtures.
