# Git-Scoped Recipe Command Authority

@lineage Reuse the proven shape from `R:/Code/pk`: checked-in XML recipe provenance, typed recipe validation, `Bun.secrets`, repository identity, broker-owned masked entry, receiver-specific leaf execution, lifecycle status, and agent observability. Do not create a runtime dependency on `pk`; this contract is self-contained and intentionally replaces its native-executable hash gate.
@authority Authority is a nonsecret broker grant that binds one exact validated recipe revision to a local user, canonical Git worktree, repository identity, recipe-relative path, credential slot set, permitted operations, delivery mode, and expiry. A digest may compactly identify the recipe revision but is not itself authority or a code-integrity claim.
@git A secret-bearing recipe must be a regular checked-in file inside a canonical non-bare Git worktree. Resolve the worktree root and Git common directory without trusting the caller's cwd. Reject paths outside the worktree, symlink escapes, missing repository identity, untracked recipes, and ambiguous nested-worktree resolution.
@git_identity Derive a versioned repository identity from normalized remote identity when present plus stable Git repository facts; bind the local grant separately to the canonical worktree root so two clones do not accidentally share local authority. Strip user info and embedded credentials before hashing or persistence. Define an explicit local-only repository identity when no remote exists rather than silently using a path as global identity.
@recipe Use `pk`'s implemented XML recipe vocabulary and decoding pipeline for the admitted V1 subset: entrypoint/base status, backend receiver, source provenance, cwd, argv atoms, nonsecret env, params, lifecycle/stop policy, ports, probes, completion, and temporal fields only where implementation and tests prove them. Add broker credential-slot declarations as a versioned extension. On Windows, executable recipes resolve to PM2 unless an internal bootstrap/test policy explicitly admits `direct`; observe-only remains nonexecuting. The recipe never contains a secret value or keychain lookup name.
@recipe_revision Compare the validated semantic recipe shape rather than raw XML bytes so whitespace, attribute order, newline style, and equivalent serializer output do not force approval. Persist either the normalized typed snapshot or a versioned digest of it with the grant. The comparison exists to detect a changed authorization request, not to authenticate executed code.
@no_code_hash Do not require hashes of executables, interpreters, scripts, package manifests, lockfiles, source trees, modules, plugins, or dependency closures. Such hashing invalidates ordinary high-velocity interpreted development while still failing to capture all executed code. The vetted recipe and repository-scoped grant are the intentional security seam.
@entrypoints Permit native tools, scripts, interpreters, Mise tasks, uv entrypoints, and other argv-safe commands represented by the admitted recipe schema. Reject opaque shell command strings and secret-bearing argv, but do not reject an entrypoint merely because its implementation is interpreted or changes during normal development.
@copy Copying an unchanged vetted recipe into another repository carries review knowledge only. It does not carry the originating local grant. The destination broker verifies the new Git identity and worktree, displays the recipe request, requires explicit key-entry or encrypted-CAR import approval, and creates a separate destination grant.
@invocation The runner sends repository/recipe location and requested operation through authenticated IPC. The broker independently resolves Git identity, verifies tracked status and containment, parses and normalizes the recipe, compares its approved revision and credential slots, checks expiry, and only then acquires secret values and interprets the leaf execution.
@environment Preserve the recipe's declared execution model and make credential additions explicit. Reject duplicate credential-slot names, case-folding collisions on Windows, NULs, invalid platform names, and secret-bearing argv. Environment inheritance policy is recipe/receiver-owned and visible in status; never silently add unrelated broker credentials.
@execution Interpret the validated recipe through the receiver-specific lifecycle using argv arrays and explicit cwd where applicable. The broker owns credential acquisition and lease lifetime; the recipe runtime owns output streaming, status, timeout, cancellation, readiness, exact cleanup, and finalization.
@observability Authorized leaf output is agent-visible according to recipe policy. Provide live/tee/structured modes, bounded stdout/stderr tails, stream offsets and timestamps, heartbeat cursor polling, process identity, probes, readiness, failure facts, and next actions. Do not claim automatic redaction of a credential printed by the authorized child; this V1 assumes vetted recipes and a well-behaved agent.
@drift Repository, worktree, recipe revision, credential-slot, grant-generation, or expiry drift fails before secret acquisition. Changes outside the recipe—including interpreter, script, package metadata, lockfile, dependency, and application source changes—do not invalidate an unchanged recipe grant.
@proof Cover native and interpreted entrypoints; Mise and uv routes; equivalent Git remote normalization; clone/worktree separation; copied recipe requiring destination approval; untracked and symlinked recipes; nested repository ambiguity; semantic recipe normalization vectors; recipe/slot/grant drift; ordinary source/package churn without reapproval; observable output cursors/tails; Windows environment-name collisions; expiry/revocation; and absence of broker-originated secret logging.
